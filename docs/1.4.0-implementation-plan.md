# AMI 1.4.0 Implementation Plan

This plan tracks the 1.4.0 feature branch scope. Keep implementation slices small, testable, and safe across Forge and
NeoForge. Prefer metadata, facets, tags, and string class names over hard mod class references.

## Release Goals

- Improve major mod classification coverage without increasing crash risk on missing or loader-specific mod APIs.
- Add player utility search from issue #30: player heads, online player actions, map/waypoint actions, and admin actions
  where permission/context is known.
- Reduce context-menu clutter with grouped submenus.
- Validate UI/runtime behavior with deterministic tests first, then AutoMine smoke where visual/runtime contracts matter.

## Workstreams

### 1. Classification Foundation

- Migrate remaining raw `path.contains(...)` family-prior routing toward compat facts, stable facets, and `PathTokens`
  exact token/phrase checks.
- Add false-positive tests while migrating each rule.
- Keep `docs/classification-routing-log.md` current for every new compat rule or routing policy.
- Use runtime dumps to validate visible grouping/collapse only after focused JVM tests pass.

### 2. Compat Coverage

- TConstruct and Silent Gear:
  - Preserve existing Modular Gear focused buckets for parts, modifiers, stations, blueprints, tools, weapons, armor, and
    materials.
  - Implemented semantic gaps from the Prism dumps:
    TConstruct generated fluid-container variants reclassify after metric facets and resolve to `utility/misc`; Silent
    Gear fuel recipe-use metadata resolves to `ingredients/fuel`.
  - Validate Silent Gear material/runtime trait indexing against existing tests.
- Mana and Artifice:
  - Implemented the next MNA slice: artifice/sorcery items, faction horns, patterning prism, ender disk,
    manifest/ledger, healing poultice, thaumaturgic links, transitory tunnels, magic brooms, Vinteum/silk/material
    paths, utility tools, weapons, staves/wands, relic melee classes, ritual utility paths, HUD badges, and MNA
    dust/crystal tags.
- NeoForge dump candidates:
  - `ArsNouveauCompat` for glyphs, ritual tablets, magic artifacts/reagents.
  - AppMek support through AE2/Mekanism-family facts for chemical cells and P2P tunnels.
  - `SpectrumCompat` for reagents, pure resources, structure placers, and cloaked/conditional items.
  - `NaturesAuraCompat` for effect powders, tokens, structure finders, aura tools/artifacts, and powder variant collapse.
- Forge dump secondary candidates:
  - Twilight Forest, Hexerei, Celestial Core/Artifacts after the higher-priority compat slices.
  - Treat Alex's Caves/Mobs and TacZ as validation targets unless new failures appear.

### 3. Player Utility Search

- Implemented core `^name` as a transient player utility search surface.
- Return player-related nodes for:
  - implemented: player head item nodes for valid typed names, online names, and local history
  - implemented: online player utility nodes when the client connection exposes one
  - implemented: map/waypoint-capable player metadata when a provider is available
- Implemented metadata for player name, UUID, online state, known dimension/position, coordinate source, and waypoint
  providers.
- Implemented suggestions ranked as online players first, then local history, then substring matches. Suggestions and
  results are config-capped to avoid search-result spam.
- Player heads:
  - implemented: create player-head stacks through platform helpers
  - implemented: give named heads from player utility nodes
  - implemented: record history after player-head cheat-give actions
  - implemented: start with reliable skull rendering through registered synthetic stacks
  - implemented: optional full 3D player rendering behind config, fail-closed to fallback rendering

### 4. Player Actions, Maps, And Waypoints

- Implemented provider registry/facade under `xplat/src/main/java/com/sanhiruzu/ami/player/`.
- Provider implementations are optional and no-crash:
  - implemented detected providers for Xaero Minimap/World Map mod ids
  - implemented JourneyMap provider with copy/export fallback and reflective client waypoint creation only when its native
    waypoint classes can load
  - implemented FTB Chunks provider with reflective client waypoint creation and copy/export fallback
  - implemented manual coordinate copy fallback when exact coordinates are known
  - deferred: direct Xaero native waypoint creation until a stable non-GUI API is proven
- Context actions:
  - implemented: copy player name
  - implemented: give player head, when cheat mode/admin gate allows
  - implemented: copy waypoint data for available map providers when exact coordinates are known
  - implemented: add native JourneyMap waypoint action through the provider registry when exact coordinates are known and
    the native waypoint API can load
  - implemented: add native FTB Chunks waypoint action through the provider registry when exact coordinates are known
  - implemented: teleport to player / teleport player to me only when admin capability is known or safely command-gated
  - deferred: direct "add waypoint" action for Xaero after a stable API is proven
- Implemented clean degradation when the client cannot know another player's position.

### 5. Context-Menu Submenus

- Group the current flat action list into stable submenus:
  - implemented: Crafting
  - implemented: Recipes
  - implemented: player Waypoints/Admin submenus
  - implemented: Cheat
  - implemented: Filters
  - implemented: Pokemon/Cobblemon

  - implemented: Debug/developer
- Preserve action IDs and policy/config compatibility.
- Added menu primitive tests for submenu navigation, provider action failure handling, and builder tests that assert grouped

### 6. Menu Polish

- Polish search help, config labels, submenu spacing, hover states, and long text behavior after the functional work.
- Implemented `^` help text, player utility config descriptions, submenu spacing/hover behavior, and bounded submenu text.
- Numeric player utility config fields are clamped by slider metadata and search-time result/suggestion caps.

### 7. Runtime Validation

- Prefer JVM tests for classification and result shape.
- Use `ResultsTreeDump` / runtime mirror tests for grouping/collapse regressions.
- Use AutoMine smoke for inventory overlay rendering. Current AutoMine helper actions can open inventory and screenshot but
  cannot yet type an AMI search query or right-click a result row, so player utility search, context-menu map actions, and
  3D player-model interaction are covered by compile/JVM tests plus fail-closed runtime code paths until richer helper
  actions exist.
- Run FTB Quests fixture smoke after context-menu or quest action changes.

## Suggested Order

1. Classification foundation and small semantic resolver gaps.
2. TConstruct/Silent Gear and MNA next slice.
3. Ars Nouveau, AppMek, Spectrum, and Nature's Aura.
4. Player utility search core.
5. Player map/waypoint/admin actions.
6. Context-menu submenus.
7. Menu polish and runtime smoke.
8. Final dump validation, docs, and release notes.
